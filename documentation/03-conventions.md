# Conventions

## Naming
- Java: `PascalCase` types, `camelCase` members, packages lowercase. Use cases named by intent (`RegisterBusiness`, `InviteEmployee`).
- TypeScript: `PascalCase` components, `camelCase` functions, kebab-case file names, strict mode on.
- Branches: `feature/<scope>-<short>`, `fix/<short>`. Commits: Conventional Commits.
- Env vars: `UPPER_SNAKE_CASE`. Permission codes: `domain.resource.action`, for example `billing.invoice.void`.

## API
- Base path `/api/v1`, plural kebab-case resources, JSON only.
- Tenant comes from the auth token, never from the URL or body. The active branch is selected by `X-Branch-Id` and validated against `branch_access`.
- IDs are UUIDs. Timestamps are ISO-8601 UTC. Money is `{ "amount": 12500, "currency": "INR" }` in minor units.
- Pagination: `page`, `size`, `sort`. Responses return `items`, `page`, `size`, `total`.
- Errors use RFC 9457 `application/problem+json` with `type`, `title`, `status`, `detail`, `code`, `traceId` and field `errors[]`. One global `@RestControllerAdvice`.
- Mutating endpoints that must be retry-safe accept `Idempotency-Key`.
- OpenAPI generated by springdoc and served locally at `/swagger-ui`.
- Controllers are thin: validate, authorize, call one use case, map to DTO. No repositories in controllers.

## Database
- Flyway only, in `database/migrations`, named `V<nnnn>__<snake_description>.sql`. Applied migrations are never edited.
- Tables and columns `snake_case`, tables plural. PK `id uuid`. FKs `<entity>_id`. Constraint names: `pk_`, `fk_`, `uq_`, `ck_`, indexes `ix_`.
- Every tenant table has `business_id NOT NULL`, tenant-safe composite FKs and an RLS policy.
- Audit columns on every table: `created_at`, `created_by`, `updated_at`, `updated_by`, `version` for optimistic locking.
- Soft delete (`deleted_at`) only for master data. Financial, inventory and audit records are append-only.
- Important transactional data is relational, not JSON. `jsonb` only for genuinely schemaless metadata.
- Roles: `misva_owner` runs migrations; `misva_app` runs the application and has no DDL, no superuser, no `BYPASSRLS`.

## Security
- Passwords hashed with Argon2id or bcrypt; access tokens short-lived, refresh tokens rotating and stored hashed in `auth_sessions`.
- Authorization via permission checks (`@PreAuthorize`) resolved from roles and branch access, never from role names in code. Subscription gating via entitlements, never hardcoded.
- Never trust client-supplied tenant identifiers. Every repository query is tenant-scoped; RLS is the backstop, not the only guard.
- No secrets in source. `.env` is git-ignored; `.env.example` holds placeholders only.
- Clinic data: separate permissions, access logged to audit, no export through generic endpoints.
- Logs are structured JSON with `traceId`, `businessId`, `userId`; no PII, tokens or passwords in logs.
- Rate limiting and lockout on auth endpoints; CORS restricted to configured origins.

## Testing
Unit tests for domain rules, integration tests against real PostgreSQL (Testcontainers or a dedicated test database), API tests for each endpoint, and a mandatory cross-tenant isolation test for every tenant-owned resource. Playwright E2E for key workflows.

## Development workflow
1. Inspect existing code and docs.
2. State intended change; get approval for scope.
3. Implement on a feature branch in small commits.
4. Run build, tests and migrations locally.
5. Review the diff; update docs.
6. Report completed work and open issues. Nothing is called done unless verified.
Architecture changes require written approval before implementation.
